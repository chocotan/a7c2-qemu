# 参数副本与76块快照的实际数据根

当前d64参数副本不能直接供应完整76块快照。关键区别是`T[0]=S`，而`T[4]=S+2950`、`T[13]=S+3e80`；后两者已超出d64复制范围。不能把getter相对这些子根的字段偏移套在参数P上，也不能用common/default的已知零字节填补它们。完整provider继续返回ENODATA。

范围为只读公开ALLLANG CP原件；不运行VM、不使用真机/物理SD/private/full数据、不修改运行时协议或ready状态。该目录保存源判断和一个常量片段合同，没有增加能放行2040的provider。

## 可编码字段与缺失来源

以下映射可实现为有源字段consumer，但当前缺少对应子根和缓存输入，必须返回ENODATA。C表示getter缓存基址；完整collector写头`+0=6,+2=u16(command),+4=u32(0)`，字节+1及尾部保留字节不能默认为零。

| command / getter | 输入→packet输出 | C | 仍需来源 |
|---|---|---|---|
| 2001 / 8d4a00 | S+2a27 → +8，1B | 1658d20 | 字段、C+1及C+9..b |
| 200d / 8d58d8 | S+2a28 → +8，1B | 1658d50 | 字段、C+1及C+9..b |
| 2017 / 8d5f60 | S+2a51 → +8，1B | 1658e08 | 字段、C+1及C+9..b |
| 2019 / 8d5f92 | S+2a55 → +8，1B | 1658e28 | 字段、C+1及C+9..b |
| 201a / 8d5fc4 | S+2a56 → +8，1B | 1658e38 | 字段、C+1及C+9..b |
| 206e / 8d7eaa | S+2aa4 → +8，4B | 1659310 | 四字节字段及C+1 |

2020 getter先读T[0]+d54；值为1..3才复制参数+e4..e7到packet+8..b，其他值保留缓存1658f70..73。当前common/default的P+d54为已知0，因此选择的是未知缓存。即使后续模式改为1..3，packet+1的来源仍需补齐。

## 唯一已闭合的常量片段2012

`8d5cfa`在force=1时从文件VA cf5a68加载三个u32、写完整12字节并返回0xc。文件原值是`000000000000000000007700`。collector覆盖其明确头字段后，片段为：

```text
060012200000000000007700
```

它的12字节可全部标已知，因为保留字节+1和payload+8..b都有明确文件来源。这个常量不依赖P、LIF或配置服务，但单个片段不能组成完整2040，也不证明原生发布或generation。

[source-pins.json](source-pins.json)给出独立重读的四个窗口，共82字节；原件身份、完整表与原collector等上下文沿用链接的既有源合同。主会话已重算四窗口摘要并核对根绑定和常量加载指令。没有使用BSS零、缓存默认值或旧run回填。`full_provider_complete=false`、`capture_verified=false`保持。
