# 交互输入调查：撤回未经证实的根因判断

当前GTK手动按键未通过最终验收。自动确认推进首设、显示拍摄UI，与手动交互可用是不同验收项。

此前排查存在以下错误，后续不得沿用：

- FRAME_DRAW的8条和FRAME_SEM_WAIT的128条是日志上限；不能说明只执行这些次数或已经停止。
- live模式曾将常规日志指向/dev/null；只在非live诊断阶段追加的日志不能用数量与实时OBS日志比较。
- 必须匹配每个run的AppFw线程和映射，不能跨run固定使用292/299。
- 原input_infra_callback成功路径仅分配、复制、设置source、发送，没有已证的线程亲和性检查。
- 早期收到的0x0c000003事件发生在人工按键之前，不能称为人工0x30事件被改写。
- 图像或截图摘要变化可能仅由光标/控件焦点造成；必须比较原LCD高亮/页面及接收记录。
- “收到请求”“发送返回0”“调用原callback”均不足以证明App实际消费和UI处理。

最新确定问题：GTK3导入时PyGObject自动处理sys.argv，入口自身的`--display gtk`被当作
X显示地址。`menu-native.py`现仅在导入面板期间隔离argv，再恢复原参数。
真实CLI参数下创建GTK面板的host测试已加入`test-ui-native.py`并通过；不涉及guest按键。

接下来使用唯一串口owner在一次人工键后读取AppFw线程栈及原模块映射，原样保存为
`live-input-stack.txt`。只有当前等待对象和生产者闭合后才修改同步逻辑，不再盲加信号量释放。
当前邮箱单槽/u32序号等缺陷仍需修复，不能当作最终交付输入通道。
