# Functional original-MPR codec adapter

This is an implemented in-process codec backend for the explicit `virtual-functional-camera-v1` profile. It accepts the original MPR recording transport, calls the real shared functional-camera bridge, converts returned H.264 bytes, and publishes into the original MPR-owned ES/VideoInfo buffers. The original MPR/Fsys writer remains the only media-file writer. **This handoff is compile-only: parent integration, original-MPR mux/Fsys acceptance and independent SD-file decode have not run. `capture_verified`, physical-ASIC verification and original-CP verification remain false; the strict native gap mask stays 63.**

Scope of this focused handoff is the codec C/header, its C/Python fixtures and this README. Existing memory, runtime/profile/build, shared ABI/bridge, source pins and original binaries are untouched. No pytest, C scenario, VM, original SDK-binary read, private/full data, network, dependency installation, device or physical SD was used. The later explicitly requested guest ABI check read only the public libc/libdl/libpthread/loader 2.25 as linker/symbol inputs. Compiler-created host/AArch64 artifacts were temporary and were not executed. Report flavor is ordinary reverse engineering (`null`).

## Admitted functional contract

The exact destination/source pair is `8055001f` / `80c70047`; request size is exactly 48. Other message IDs delegate, except `1610` dual/multi-open forms explicitly fail `ENOTSUP` in this profile.

| Original message/command | Declared parameter bytes | Actual operation |
|---|---:|---|
| `210/0`, one codec `20`, view zero | `98` hex | Snapshot original live buffers; real bridge INIT |
| `210/1` | `80` hex | STATE, VIDEO_BEGIN, first real VIDEO_FRAME; publish before Start event |
| `210/2` | `4` | Explicit `ENOTSUP`; shared model has no force-IDR operation |
| `210/3` | `10` hex | Finish preceding worker work, real VIDEO_END, verified EOS, native control-end slot |
| `210/4` | **zero** | Drain if live, real CANCEL, erase lease and quiesce before Close event |

The close length is source-defined zero even though the original caller copies a 16-byte close parameter to the fixed area. It must not be changed to 16 by inference. `P=wire+8` and `V=wire+28` remain independent domains; the adapter reads the parameter snapshot through V only.

Functional v1 interprets `A+68/A+6a` as little-endian width/height, bounds even dimensions to 1920×1080, and uses logical 30 fps with low-delay AVC packets, `PTS == DTS`, duration one. It accepts audio format `A+65 == 3` and requires the complete selection byte `A+88 == 0`. **Byte65 is not proof that Audio Recording is Off**: the parent must separately select and verify original FHD/AVC settings and Audio Recording Off through the original UI. Unsupported audio formats and real dual/multi-codec forms still fail. The implementation supplies no audio bytes or audio-ready substitute. Quality/exposure/focus configuration is retained from actual bridge STATE when starting video.

`A+10/A+18` are the secondary ES base and byte capacity, not a second codec/format declaration. The original table's **8 MiB** type4 arena is admitted when its complete span maps into the current owned arena, its logical address matches the provider's software IOVA, and its group/generation agrees with main ES and metadata. That range is leased but never encoded into or cleared by this adapter. A missing base, wrapping/cross-arena span, foreign/retired range, wrong domain or wrong group/generation fails. Wire second codec/format fields and nonzero selection byte remain rejected. `A+28` has opaque auxiliary units: only the optional auxiliary address is owned with a one-byte pin; no capacity or byte extent is inferred from that u16. These are explicit software contracts and make no physical ASIC-layout claim.

Native timestamps use 90,000 ticks/second: the original sample conversion at `222dc0` passes 90,000 as its input scale. Thus the defined 30 fps stream publishes 3,000 ticks/frame. Wall-clock pacing is software scheduling and is not camera oscillator calibration.

## Buffers, publication and completion

Original `EncOpen` stores virtual addresses before converting A. The existing `nvideo_parse_encopen_parameters()` parses the immutable whole open snapshot, preserving optional secondary capacity and opaque auxiliary units. The adapter validates the live ES triple at `3b7d68`, PI base/count at `3b7f70/3b80b0`, independent read/write pointers at `3b7e58/3b7e68`, and their pre-conversion triples against that snapshot. Write cursor means original write base **plus four**. The frame-status pointer at `3b8168` must match that independent write base. Initial cursors and status count must be zero; declared spans must be owned and disjoint where required.

The open retains main/secondary ES, PI (`count*96`), read-control (`0x294`) and independent write-control (`0x330`) leases in one current record group/generation, plus the optional auxiliary address pin. Only counter at write-base and cursor at write-base+4 are written in that control span; original private gates and condition variables are untouched. Each nonempty request parameter snapshot instead borrows the separate 512-byte type2 fixed area, validates V and its paired logical P through the provider, copies only the declared bytes, and releases before bridge/native I/O calls. Fixed memory is not treated as part of the record generation.

Returned 96-byte functional headers are validated separately from original VideoInfo96. Actual Annex-B configuration and packet NAL bytes become BE32-length NALs. The actual existing parameter-set and normal-AU consumers validate the converted bytes. A type-4 SPS/PPS descriptor precedes the first normal type-0 sync sample; later frames use type 1. Configuration changes and reordered/delayed packet coordinates outside v1 fail explicitly. No NAL payload is generated by the adapter.

Before every ES, PI, cursor or frame-counter write, the adapter validates all record borrows. The actual `functional_mpr_memory_write(lease, offset, immutable_input, bytes)` serializes destination validation, copy and digest readback with Free/retirement; the codec has no generic `/proc/self/mem` writer or duplicate readback policy. A retired destination token cannot write even while its old bytes remain mapped. A verified ES extent stays permanently reserved for that open even if later metadata publication fails. PI is written first, followed by a release barrier (`DSB SY` on AArch64), the independent write cursor, and then the source-proven frame counter for a normal frame. These are separately serialized writes, not a rollback transaction; failure retains the actual successfully published prefix.

Setup/request-release/worker error paths release their borrows. Close releases after its actual drain/cancel sequence and before its original event; shutdown retries retained cleanup only after Close. A bounded token ledger preserves every failed release even after the local job/open is cleared. `owned_memory_leases` counts those tokens, and `last_memory_release_error` preserves the exact error. Memory shutdown consequently continues to refuse live tokens. No adapter mutex is held over native I/O callbacks, bridge RPC, or memory acquire/validate/write/release calls.

PI cursors follow the last-processed-slot convention. Returned slots are counted from the actual original shared-read cursor; the adapter never advances it. Two slots remain reserved for drain/EOS while recording, because a synchronous Stop can hold the original API lock. Rings need at least five slots. Backpressure prevents another frame operation; it is not counted as an encoded frame or successful drop. A bounded drain wait returns a real error if the consumer cannot make room.

**ES never wraps or reuses bytes during an open.** Recording length is bounded by the original ES capacity; exhaustion fails `ENOSPC`, retains the successfully published prefix and emits original encode-error event `4e0/0b`. An individual bridge result is bounded to 8 MiB. This avoids claiming an unclosed asynchronous ES-retirement lease. Upgrade only after an actual native completion/retirement contract is implemented.

Successful completion messages are actual allocated 48-byte original-transport events: `4e0/{1,3,7,9}`. Original `ConvertAvconEvent` maps them to expected open/start/stop/close events, and original `CallbackFromAvbbc` performs its own mutex/condition-variable handling. Backend errors remain in `PayloadCodec+14` and snapshots/logs. A single worker serializes commands and frame production, so Stop/Close have no independent frame thread to race; drain/quiescence precedes their events. Scheduler reservation clears before event send, allowing an early original reply receiver to issue the next command even before `send()` returns.

All bridge and OSAL callbacks run outside adapter locks. PID checks precede inherited locks. Reply ownership is tracked before bytes are touched; failed frees stay owned with their exact error. Overlapping allocator returns are rejected without overwriting/freeing the original lease. Numerically unusable allocator pointers are quarantined and remain visible as retained ownership.

**Observe actual Close consumption.** The first verified original receive emits `FUNCTIONAL_MPR_EVENT_RECEIVED`; an actual successful original event free emits `FUNCTIONAL_MPR_EVENT_FREE`. Both contain `seq`, `command`, `wire_fnv`, `src`, `dst`, `received`, `rc`, `state`, `pending` and `owned`. Sequence identifies the event allocation; FNV covers its exact immutable 48-byte wire, including the native operation error at +14. `command` is the original request command (Close is 4), `src=0x8055001f`, `dst=0x80c70047`, and `owned` counts retained replies. Duplicate receive observations do not duplicate the receive log. Log `rc=0` means receive verification or actual free succeeded, not that the operation error in the event was zero. A freed event never observed by the original receiver has `received=0` and cannot prove consumption. Successful `send()` advances only `events_sent`.

The runner must match the last actual Close's receive and free by sequence/hash with `received=1`, then separately verify original mux/Fsys finalization. `shutdown()` requires `state==FMPR_CLOSED` with no pending/reserved/queued/working command; Open, Recording, Drained and active Fault states return `EBUSY` without changing the clip or issuing Stop/Cancel. The worker exit path performs no bridge cancel. A completed Close may be quiescent after a confirmed cancel while its real earlier drain/cleanup error remains in the event/snapshot. That is not a successful recording result. Shutdown joins only this already-closed adapter and reports retained reply/memory ownership; it cannot stand in for original Stop, mux or Fsys drain.

Snapshots distinguish accepted model packets (`backend_frames`), normal PI commits (`frames_published`), all PI slots (`pi_published`), ES readback bytes, actual event observations and original shared-read slots returned. Frame-counter failure after a normal PI commit still leaves that committed frame counted. None establishes original file consumption or capture acceptance. `memory_generation` identifies the current open's record generation and clears on Close. Causal logs retain native Start hash, model instance, epoch, frame generation, converted byte hash, timestamps and capacity after the original request is freed.

## Join actual runtime bytes

The runtime-content follow-up adds the following **source-implemented, unexecuted** receipts. It changes no shared ABI, bridge, broker, menu, memory provider, Fsys writer or checker. All hexadecimal bodies come from copied request/event bytes or validated PI readback; media bodies never go to stdout as hex. FNV means FNV-1a64, a byte-consistency digest, not authentication. The parent broker's bounded binary transfer trace supplies the actual model Annex-B bytes; this codec creates no media or trace file.

| Tag | Exact added fields and meaning |
|---|---|
| `FUNCTIONAL_MPR_REQUEST` | `request_seq command rc pid producer_tid src dst native_bytes native_fnv epoch memory_generation instance wire_hex`. `wire_hex` is all **48** original dispatch bytes; `native_fnv` covers those same bytes. `request_seq` is the process-local immutable request association, including gaps from failed reserved requests. `rc` is the actual validation/release result. The first Open's request-time `instance` may be zero before its real INIT; the subsequent Open/event binds the actual instance. |
| `FUNCTIONAL_MPR_OPEN` | Existing geometry/P/V fields plus `epoch instance request_seq native_fnv memory_generation es_address info_address read_address write_address counter_address es_correction`, observed from the current original getters/globals and acquired record generation. |
| `FUNCTIONAL_MPR_ES` | `epoch instance native_start_fnv request_seq call_request_seq call_native_fnv memory_generation group es_token address offset bytes avcc_fnv nal_count nal_payload_fnv frame_generation packet_sequence model_token result_bytes source_offset source_bytes source_fnv info_type pid observer_tid rc`. The actual destination is `address=main_ES+offset`, within the held `es_token`; `bytes/avcc_fnv` cover its complete checked readback. `source_offset/source_bytes/source_fnv` identify the exact raw Annex-B configuration or AU interval in the complete `model_token` result. `call_*` names the actual Start or Stop request causing that bridge return; `request_seq/native_start_fnv` retains the clip's original Start. |
| `FUNCTIONAL_MPR_PI_PUBLISH` | `epoch instance native_start_fnv memory_generation group pi_token es_token request_seq call_request_seq call_native_fnv model_token result_bytes ticket slot slot_generation cycle frame_generation es_offset es_bytes es_fnv read_address read_token control_token read_before read_after read_seen write_before write_after observed_write counter_before counter_after outstanding_before outstanding_after pid observer_tid info_address info_hex rc`. `info_hex` is **96 actual PI bytes**, read back and compared before cursor publication. Slot address is `info_address=original_PI+slot*96`. The cursor write is separately checked through the real provider. Counter and read/write snapshots are actual loads around this publication. |
| `FUNCTIONAL_MPR_PI_RETURN` | The same fields identify the retained publication, but `read_before` is the previously validated native read cursor and `read_after` is the new actual read-control value. Every returned ticket has its own copied `info_hex`, ES identity, slot generation and cycle. `outstanding_before/after` delimit the complete observed cursor advance. No producer-written write cursor or frame count emits this tag. |
| `FUNCTIONAL_MPR_PACKET` | Existing packet/timebase/capacity fields plus `memory_generation request_seq ticket slot slot_generation model_token counter_before counter_after read_after write_after es_address es_offset es_token`. Its `avcc_fnv` is actual ES readback. The counter snapshots surround the real normal-frame counter write and readback, **after** the corresponding PI cursor commit. |
| `FUNCTIONAL_MPR_EVENT_RECEIVED`, `FUNCTIONAL_MPR_EVENT_FREE` | Existing `seq command wire_fnv src dst received rc state pending owned` plus `pid observer_tid receiver_pid receiver_tid producer_pid producer_tid instance epoch memory_generation request_seq native_fnv reply_address operation_error wire_hex request_hex`. Both bodies are the complete **48** bytes. `seq/reply_address` identify the event allocation; `request_seq/native_fnv/request_hex` retain its original request. `operation_error` decodes signed event `+0x14`; `rc=0` describes actual receive validation or original free, not operation success. Close retains its original memory generation even after releasing the live lease. |
| `FUNCTIONAL_MPR_EVENT_FREE_FAILED` | Same copied event association with the actual nonzero original release `rc`; it retains ownership and cannot satisfy successful free. Emitted only when the original free was actually attempted after validation. |
| `FUNCTIONAL_MPR_OPERATION` | Existing operation/event errors plus `request_seq epoch memory_generation instance pid producer_tid`, associating the actual command outcome with its copied original request. |
| `FUNCTIONAL_MPR_RECEIPT_ERROR` | `stage=event|pi rc=-75` if bounded receipt formatting overflows. This is missing evidence, never a truncated positive receipt. |

`nal_payload_fnv` covers the concatenated NAL payload bytes in order, excluding AVCC length words. The whole `avcc_fnv` additionally binds each BE32 length and every boundary. To compare representations, the independent checker must read the broker's actual `model_token` result, select the exact `source_offset/source_bytes`, verify `source_fnv`, parse its actual three/four-byte Annex-B delimiters, and reconstruct the exact ordered BE32-length bytes. Compare length, NAL count, ordered payload digest and whole AVCC digest to this current leased ES extent, then parse `info_hex` and join the same NAL payloads to actual original MPR/Fsys MP4 sample contributions. Annex-B, AVCC and whole MP4 hashes are different domains and must not be equated.

The PI ledger has one bounded descriptor per native slot (at most 65,535). A publication `ticket` increases within an Open epoch; `slot_generation` increases on reuse of that physical PI slot and `cycle=ticket/pi_slots`. Metadata can be overwritten only after the actual native read cursor returns the prior ticket. Before counting an advance, `ring_space()` validates the current record generation, write cursor, returned distance, every retained ticket and each still-unoverwritten 96-byte slot; it then reloads the frame counter and validates the lease again. Only the original shared-read cursor advances retirement. Production does not call the HOST_TEST `nring_advance_read` fixture or write the read cursor. `observer_tid` is the codec's observing thread; it **does not claim the native cursor writer's TID**. Actual event receiver PID/TID are recorded independently by the original receive hook.

Type-4 configuration and type-7 EOS are PI publications, not normal encoded frames. EOS has zero coded extent and cannot increment `frames_published` or produce a normal `FUNCTIONAL_MPR_PACKET`. A failed later counter write can leave an irreversible normal PI prefix counted, with no successful packet-counter receipt; the real failure/event must reject whole-job acceptance. Rejected dispatches, malformed native cursors, stale generations and failed writes produce no successful consumption receipt. No logger callback runs under the codec's mutex, and free receipts use retained copies after actual free, never dereference freed events.

Each record payload is bounded below the existing 1,024-byte sink limit; `record()` is void, so storage/console I/O success cannot be asserted here. The parent must retain and hash the complete console, mirror the required tags, and fail on receipt omissions, formatting errors or truncation. Final acceptance still requires original AP -> actual CMOS/encoder -> original MPR/Fsys -> independently decoded virtual-SD files. No receipt sets a verification boolean.
