# 固定曝光参数的原编码：静态证据

2.01 ALLLANG 的 F4、1/125 秒、ISO100 编码已由原候选表、格式化／转换逻辑和 CP getter 交叉核对。**原曝光查询、上游设备状态和实际曝光尚未完成**；本目录不构造快照、不写 AP holder、不接真机。

## 编码与条件

| 参数 | 规范原值 | 条件性完整快照中的字段 | 原 CP getter（CPVA） |
|---|---|---|---|
| F4 | u16＝400＝`0x0190`，LE `90 01` | `snapshot+1d4`，201b 子块+8 | `8d5ff6` |
| 1/125 秒 | 分子 u16＝1、分母 u32＝125 | `snapshot+134`、`+138`，200e 子块+8／+c | `8d590a` |
| ISO100 | CP u8＝`0x0b` → AP 枚举5 → 数值100 | `snapshot+28c`；伴随 `+28d` 为0才转换 | `8d68d2`（2036） |

偏移仅在此前子块均完整返回时成立：原 getter 可能因错误返回0，forced 也不保证完整。不得按这些固定位置生成全零成功包，或把快门两值中间的另一 u16 当作有理数的一部分。

## 可复核原路径

- F4：具名 formatter `translator_mp_aperture::translate@23dc188` 在 `23dc2cc` 读 model+a0 的 u16，再除100生成整数位、余数除10生成小数位；`5eedd6a/5eeddba` 两张候选表的规范值均400。仅看到“4.0”字形不足以区分400..409。
- 快门：AP `4c7da1c` 的12B为 `{1,125,37}`。`352a094` 按12B遍历并比较输入分子／分母，命中后取该域枚举37；不能把37推广到其它枚举域。`23aa34c` 的常规格式化分支做分母÷分子。CP getter 从 `D+da:u16`、`D+e0:u32` 原样写缓存 `1658d60+8/+c`；AP `35190d0/e4` 分别读取。
- ISO：AP `41b0918` 记录 `{5,100}`；`3521310` 的通知转换先减7，输入11经原跳表到 `3521364` 生成枚举5，`get_iso_value` 的 `2d4bf5c` 返回100。`3549688` 检查伴随标志非0便跳过转换，不能只改 CP 字节。CP 从 `D+113/+114` 写缓存 `1659020+8/+9`。
- 上述 CP context 的 `D=*(context+10)`；`b2ebe6..ec` 建立 `D=B+2950`。工作态更上游写入者、AP holder 更新的完整通知链、实际快门／增益消费仍未闭合。

## 本机复核

在官方资产已按本成果导入后执行（只用 Python 标准库）：

```bash
python3 report/exposure-encoding/verify.py
```

脚本重算原 AP／CP SHA256，按 AP ELF PT_LOAD 映射地址，核原字节及两级 ISO 跳表。CPVA=raw+108000，Thumb 函数指针的 bit0 单独处理。它不证明 getter 在某次真实运行中已消费数据。

原初始化／通知生产和所有权边界见 [控件、镜头与曝光边界](../control-lens-exposure-frontiers.md)。调查初稿在项目 scratch 的 task20-shutter-iso；本目录为该编码成果的交付依据。
