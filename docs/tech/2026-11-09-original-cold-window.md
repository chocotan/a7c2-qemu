# 默认窗口的原用户态冷启动

后续已补实际无参数 `./start.sh` 验收，并修复原 LCD 首帧独立 15 秒截止过早拒绝，见[默认入口实跑与修复](2026-11-09-default-cold-entry.md)。以下保留本轮直接调用 GTK ON 的原证据范围。

默认 `./start.sh` 与 GTK ON 已在源码接到 `original-init-cold`。它复用原冷启动 CLI 的 kernel/RAM0、原 init/pivot/chroot/init2 与 bootin/im/appFw 路线，再复用产品既有的输入、连续 LCD、文件读回、SD 导出和保存协议。`--boot-profile direct-bootin` 保留此前兼容入口。

最终实际窗口完成三次原冷启动：简体中文首设、原拍摄 HUD、原菜单进入与返回；测试文件完整摘要、长度与四零 Uid/Gid 读回；同一内部盘重启后文件保持；显式选择“原版”后恢复包内原文件。三次均完成真实设置导出、SD 保存、19 卷冻结和单次正常 QMP quit，owner/后裔退出后租约可重新取得。独立停止盘检查的 10 个实际挂载卷结构通过，13 份运行源码前后无漂移。结果见[机器可读收据](../../validation/original-cold-window-20261109.json)。

本轮综合驱动直接调用产品 GTK ON 和开发面板，使用独立实例；默认 `./start.sh` 的 profile 分派由 host 测试覆盖，没有另称本轮实际执行过 `./start.sh`。CLI 的旧成功、窗口的单项结果与这次综合结果分别保留。

## 同一实例和文件测试

原 init 需要持久内部盘。控制器只传已选实例路径，启动进程在准备和运行期间独占它；只有 QMP owner 及后裔真正退出才释放锁，窗口不再次获取同一运行租约。实例已有时不重新铺设官方盘。原 p7 派生适配仍保存前像和完整树校验；官方包原件只读。

开发面板和 `overwrite/` 使用同一个文件测试脚本：只接受包内已有、可恢复的 `/usr` 普通文件，拒绝符号链接、路径穿越、未知目标与变化中的源文件。应用前保存原值并完整比较，写入后核 SHA，再恢复 `/usr` 只读。同一选择的应用身份跨启动稳定，重启不再次覆盖盘上变化；选择“原版”会建立独立恢复选择，启动后仍须实际 guest 读回。

旧 RAM 启动路线的设置快照只允许导入内部盘一次；该标记写入原内部 `/log`。后续冷启动使用盘上的实际 `/setting`，不会用旧 host generation 覆盖它。此处仍只验证语言/日期与完整 Backup 文件的一致性，全部设置、原关机协议和冷启动配置复位保持未验。窗口在原冷启动下禁用旧逻辑配置复位，并说明原因。

## 保存与关闭

窗口的 OFF 和开发重启仍先释放按键触点，再做真实设置导出、原 Fsys flush、STOP、卡数据读回、实际 CANCEL/CONT 和 owner 恢复。内部盘需要原内核对 19 个卷的冻结读回。当前会话只有这次完整导出与冻结都成功，才允许控制通道 EOF 后正常 QMP quit；第二次失败不能借第一次成功记录关闭。

设置 helper 的默认 `snapshot` 保持 tmpfs 专用。新增 `snapshot-persistent-v1` 只供冷启动使用：文件系统必须为 VFAT，`/setting` 实际设备号必须匹配 `/dev/cnflasha2` 块节点，虚拟内部盘驱动必须存在，空间乘法不得溢出且留出余量。随后仍调用原 `Backup_sync_subsystem(02cf)`，校验两个 bank、原 API、完整文件长度/校验和、稳定 API、RAM 导出摘要及独立 guest SHA。不会把文件系统类型放宽后直接当作保存成功。

## 已保留的失败

- 首轮 GTK 检查在 1280 像素宽的 Xvfb 中运行，而产品窗口宽 1360。9 项实际鼠标/像素检查失败；改用 1600×1200 后 38 项 GTK 全过，原失败日志保留。host 组 376 通过、40 跳过、95 子测试通过；源冻结无变化。
- 首次实际窗口 `run-g6jou9mt` 的设置保存返回 `USER_SETTINGS_ERROR stage=tmpfs_space_guard`，实际 `/setting` 为 VFAT。菜单和文件读回单项通过，SD 保存与同盘重启没有通过。独立保全全部五个 QEMU 实际 RAM 段、原错误及内部盘后，正常 QMP quit；VM 无信号。RAM 文件 25,769,510,363 字节，SHA256 `5d23b41ab0021bbd06451c6c98bc9be7667bfda72efc0ce5895920bc4ae64506`。
- 保全首轮误用 24 GiB 分配尺寸作为 ELF 文件下限，漏考虑 MMIO 空洞，读回拒绝；原记录保留。后按 QMP `query-dump` 完成字节与 `info mtree -f` 的五个实际 RAM 范围，逐段核收现有 ELF，没有重新抓取 RAM。

- VFAT 修复首轮在 guest 启动前链接失败：现代头文件生成 `stat/lstat`，原 glibc 2.25 未导出它们。改用产品已有的 `newfstatat` syscall 约定，保留实际设备号、块节点、驱动和空间判据。旧构建失败未改记成功。
- 新 C 自检先因夹具写成字面量换行而编译失败，又因夹具错用 212 块作为不足空间而断言失败；原件均保留。按真实 16KiB 块边界 210/209 修正后，严格 C11 和 ASan/UBSan 两种配置通过；生产空间公式未改。

私有原图、虚拟卡、内部盘、RAM 和原始运行输出不进入公开源码清单。

## 能力边界

这里恢复的是显式虚拟硬件下的原用户态冷链。BootROM/loader、真实 CP、原 Sony WBI、完整硬件上电、USB 宿主枚举及 jiritsu 认证仍独立未通过。原冷启动暂不接目录/256GB host SD、预览注入或隔离 USB 网络组合；选择这些组合需使用显式兼容入口，运行器不会静默换设备。

拍摄写卡和完整 BODYDATA 更新依用户约定暂缓，`capture_verified=false`；原菜单 HUD 与主机组件检查不代表成片。
